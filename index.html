About Me

I'm a systems engineer with a focus on infrastructure software—the layer beneath applications where performance, correctness, and resource constraints define the problem space. My path started with curiosity about how computers actually execute code: memory layout, syscall overhead, cache behavior, scheduler decisions.

That curiosity led to building production-grade systems from scratch: a Unix-like shell with job control, an epoll-driven HTTP server, an LSM-tree key-value store with WAL and compaction, a custom malloc implementation with segregated free lists and thread-local caches, and distributed rate limiting and job queue systems. I care about zero-copy designs, lock-free data structures, and understanding exactly what the CPU is doing at every layer.

I work primarily in C and Go—C when I need absolute control over memory and syscalls, Go when I need concurrency primitives that don't get in the way. I'm comfortable across the stack: from kernel interfaces (epoll, io_uring, signals) through runtime internals (goroutine scheduling, GC interaction) up to distributed systems patterns (consensus, backpressure, observability).
